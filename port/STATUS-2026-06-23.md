### S10 — joystick flight input (LIVE-VALIDATED + real bug fixed)
The Sprint-9 impediment (a concurrent BoB session holding the stick) was cleared, so the
shipped SDL→DirectInput bridge was validated end-to-end — and validation **caught a real
bug**: all six DirectInput axis GUIDs (`GUID_XAxis`…`GUID_RzAxis`) were defined as the same
all-zero `BOBGUID`, so the game's classifier saw every axis as X — roll drove rudder,
throttle drove aileron, the stick axes never mapped. Fix: distinct real axis GUIDs
(`bob_stubs.cpp`) + correct per-SDL-axis order (`bob_video.cpp`, `X,Y,Rz,Z` for the Extreme
3D Pro). New `BOB_AUTOJOY` scripted-deflection injector proves the chain: roll sweep →
`axisvalues.aileron` ±29000 (others isolated); roll-hold A/B frames show the aircraft banks.
Stress 8/8.

The text-entry control (load/save savename field, visitorsbook, variant name) is now a

Sprint 11 had wrongly concluded the loadgame screen "doesn't present" — a background

### S13 — file list renders save names ("Auto Save")
Root cause: the row was drawn at y=-rowheight (scrolled off the top, clipped). `m_lVertScrollPos`
was a bogus 32 for a 1-row list because `UpdateScrollBar()` runs at populate time
(`MakeFileList`) but the port sizes the listbox client only at draw time — so `GetClientRect`
returned a zero size and the scroll clamped to a fake maxvalue. Fix (`MA_LINUX`):
`CRListBoxCtrl::OnDraw` re-clamps `m_lVertScrollPos` to the valid range from the real draw-time
`rcBounds`. The file list now shows "Auto Save". No regression.

### S14 — file-select → Load loads the save (→ campaign map)
Clicks on the CLoad file list went nowhere — the idle click handler only hit-tested the
FullPanelDial menu listbox, so `CLoad::OnSelectRlistboxfile` never ran and `selectedfile`
stayed empty → `DoLoadGame` bailed. Fix: new `ma_ole_listbox_click` routes a click on a
child-dialog listbox (id≠0) to its Select handler via the RTTI eventsink; `CLoad::filename` is
a reference to `selectedfile`, so the pick propagates; the Back/Load menu was already wired.
Validated: file-click → `evt_fire CLoad Select` → Load → `DoLoadGame` →
`CFiling::LoadGame("Auto Save.sav") → 1` → the **Korean-peninsula operational map renders**.
Crash-free; 3D path stress 4/4; Preferences combos unaffected.

### Cross-port — BoB CString `FormatV` ABI fix ported
Compared notes with the sibling BoB Rowan-engine port (`~/bob`) and pulled over its game-wide
**CString-in-varargs** fix (BoB R5.3). MSVC passes a `CString` (one pointer) to varargs by value
(`%s` reads the `char*`); the SysV C++ ABI passes a class with a non-trivial dtor **by invisible
reference**, so `vsnprintf %s` prints the object's bytes → garbage. Game-wide:
`RESSTRING`/`LoadResString`/device `.name` all return `CString`; **23 `CSprintf("%s",CString)`
sites** in MiG (mission stats, flight-task, SController device list). Preferences escaped it (labels
via RT_DLGINIT, not `CSprintf`); the un-rendered text-heavy screens would garble. `CSprintf` routes
through `CString::FormatV`, so the one fix covers all sites: numeric formats keep the libc path; `%s`
formats walk conversions and per-`%s` decide CString-by-ref vs `char*` via the `CStringData` header
signature (`/proc/self/maps`-guarded reads). Validated: standalone repro 6/6, naive path confirmed
garbling (`[,"Z]` vs `[Logitech Extreme 3D]`), 3D stress 4/4 + Preferences/loadgame clean.

## Build / run
```
g++ -m32 -no-pie port/build/{obj,obj2,objmfc,objmfc2,objole}/*.o \
  -Wl,--allow-multiple-definition -lSDL2 -lGL -lopenal -lfluidsynth -lpthread -lm -o wmig
BOB_RUN_INIT=1 BOB_DRIVE_C=<wine drive_c> ./wmig                                   # title → menus
# loadgame: title→Load Game, click a save, click Load → campaign map:
BOB_RUN_INIT=1 MA_ENABLE_MAP=1 BOB_DRIVE_C=… \
  BOB_CLICKSEQ="40,588,260;95,80,112;150,75,567" ./wmig
```
