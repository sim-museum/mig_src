### M2 — native blue sky (DONE)
- **Root cause:** the software gouraud-polygon scanconverters (`gpolyscancnvrt`, the
  `RFullPanel` infinite-strip sky path) read `currscreen->logicalscreenptr` as their
  scanline base, but that pointer drifts: the DirectDraw back-surface bits move per
  `Lock`, and the HARDWIN child-window reparent math (`HARDWIN.CPP:318`) rebases it to
  a stale ~surface-centre offset. So every software gouraud poly wrote to a
  non-presented buffer — terrain (a separate tile blitter, `DoNearAddTile`) showed,
  sky was invisible/black.
- **Fix:** `render3d` (`3DCODE.CPP`) pins `logicalscreenptr` to the freshly-locked
  surface each frame, via a new `MA_LINUX` setter `MA_SetLogicalScreen` (`DISPLAY.H`).
- **Result:** upper-half sky went 0% → ~98% sky-coloured; flies 13/14 launches × 350
  frames (1 transient X11 hang, no crash). The whitish cloud band is faithful — it's
  the engine's own `dayLighting.horizonAtClouds=(255,255,255)`, the same vertex colours
  the Windows D3D path consumes.

### M7 — joystick flight input (original Sprint-9 note; superseded above)
- Bridged the **Logitech Extreme 3D Pro** (SDL: 4 axes, 12 buttons, 1 hat) to the
  buffered DirectInput path the flight sim actually uses (`ANALOGUE.CPP::PollPosition`
  → `GetDeviceData`, *not* the immediate `ANALWIN` `GetDeviceState` path).
- In `bob_video.cpp`: `DI_EnumDevices` reports the stick; `DI_CreateDevice` /
  `GetDeviceStatus` / `QueryInterface(IDirectInputDevice2)` wired; `DIDEV_EnumObjects`
  enumerates objects so the game builds its data format; `DIDEV_SetDataFormat` **copies**
  the (stack-local) `DIDATAFORMAT`; `DIDEV_GetDeviceData` emits one buffered event per
  object per poll carrying the live SDL value at the game-assigned `dwOfs`. Axes
  `0..65535` absolute → game's `scale==0` path `axisvalues = dwData-0x8000` (centred,
  no drift). `GUID_Joystick` made distinct from the all-zero `BOBGUID`s; `GUID_Button`/
  `Key`/`POV` given real DInput values so object classification works.
- **Proven:** opens (4 axes/12 btn/1 hat), 15 objects in the format, 15 events/poll,
  resting axes read centred (roll/pitch ~0, throttle idle), flies 250+ frames crash-free.
- **Impediment (environment, not code):** a *concurrent Claude session* building/running
  the sibling **BoB port** (`/home/m/bob/build/bob … BOB_TRACE_JOY=1`, ~75 s loop) keeps
  `EVIOCGRAB`-ing the same joystick `/dev/input/event14`, which freezes the legacy `js0`
  interface — so MiG Alley (and even a standalone SDL monitor) only sees the stick's
  resting state, never deflection. Live-deflection validation needs ~30 s of exclusive
  joystick access (pause the BoB session's joystick runs). Do **not** kill that process.

## Build / run
```
g++ -m32 -no-pie port/build/{obj,obj2,objmfc,objmfc2,objole}/*.o \
  -Wl,--allow-multiple-definition -lSDL2 -lGL -lopenal -lfluidsynth -lpthread -lm -o wmig
BOB_RUN_INIT=1 BOB_DRIVE_C=<wine drive_c> ./wmig          # title → menus
BOB_RUN_INIT=1 BOB_DRIVE_C=… BOB_CLICKSEQ="40,588,231;95,588,217" ./wmig   # → 3D flight
```
